# Release Note: v0.15.0 — State rename, porcelain format, Unix-friendly output

**Fecha:** 2026-06-29
**Versión:** `v0.15.0`
**Tipo:** Feature release

## ✨ Features

### 1. `dots status --porcelain` — machine-parseable output

New `--porcelain` flag for the `status` command, inspired by `git status --porcelain`.
Outputs tab-separated lines: `<module>\t<state>\t<source>\t<destination>`.

```bash
dots status --porcelain
dots status --porcelain --state broken | cut -f1   # broken modules only
dots status --porcelain | awk '$2 == "unlinked"'    # unlinked files
```

No headers, no colors, no emoji — stable format for scripting.

### 2. `--state` values unified to `unlinked`

The internal state constant `StatePending` (value `"pending"`) was renamed to
`StateUnlinked` (value `"unlinked"`), eliminating the magic mapping between
internal and user-facing names. Now `unlinked` is used everywhere consistently:

- Porcelain output: `unlinked`
- JSON output: `"unlinked"`
- CLI flags: `--state unlinked`
- Documentation: `unlinked`

**No backward compatibility needed** — all internal and user-facing references
were updated in a single pass.
