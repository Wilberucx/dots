# Release Note: v0.13.0 — Link planning refinement, `-V` shorthand, doctor improvements

**Fecha:** 2026-06-10
**Versión:** `v0.13.0`
**Tipo:** Features / Refactor

## 🚀 Nuevas Funcionalidades

### 1. Shorthand `-V` para `--variant`

El flag `--variant` ahora tiene el shorthand `-V`, facilitando el cambio rápido de variantes:

```bash
dots link -m Git -V work
dots plan -m Nvim -V notevim
```

### 2. Simplificación del planning de links

El flujo de planificación de `dots link` y `dots plan` fue simplificado, eliminando pasos redundantes y centralizando la lógica de decisión en el paquete `internal/plan/`.

- Separación clara entre `BuildLinkPlan` y `BuildUnlinkPlan`
- Los conflictos ahora se resuelven correctamente en el plan, no durante la ejecución
- `VariantSwaps` se respetan en el plan sin necesidad de `--force`

### 3. Mejoras en `dots doctor`

El comando `dots doctor` ahora incluye:

- Verificación de detección del repositorio (markers activos)
- Diagnóstico de módulos con variantes inactivas
- Conteo de módulos Lua vs YAML legacy
- Health verdict con estilo visual (Healthy / Needs Attention / Unhealthy)

### 4. Mejoras en `dots plan`

- Nuevo flag `--format json` para output machine-readable
- Soporte para `--variant` (requiere `--module`)
- Auto-swap detection al igual que `dots link`
- Visualización mejorada con iconos y resumen por módulo

## 🔧 Cambios Internos

### Paquete `internal/plan/`

Refactor completo: `BuildLinkPlan` y `BuildUnlinkPlan` ahora producen `Actions` con tipos explícitos (`ActionCreateSymlink`, `ActionBackupFile`, `ActionReplaceSymlink`, etc.), eliminando la lógica duplicada entre `link.go` y `plan.go`.

### Paquete `internal/transaction/`

Mejoras en el manejo de errores TOCTOU: las operaciones sobre archivos que no existen ya no fallan (caso de carrera entre check y exec).
